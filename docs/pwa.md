# GlassWave as a Progressive Web App

The web build is an installable PWA: an app icon on the home screen / desktop, a
standalone window without browser chrome, and an offline-capable app shell.

## What is in place

| Piece            | Where                                                                                           |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| Web app manifest | Generated by `vite-plugin-pwa` from the `manifest` block in `vite.config.ts`                    |
| Service worker   | Generated (`dist/sw.js`, Workbox `generateSW` strategy)                                         |
| Registration     | `src/pwa.ts`, called from `src/main.tsx`                                                        |
| Icons            | `public/icons/icon-192.png`, `icon-512.png` (`any` + `maskable`), `public/apple-touch-icon.png` |

The manifest lives **only** in `vite.config.ts` — the old static
`public/manifest.webmanifest` was removed so the two cannot drift apart.

## Caching strategy

- **Precache** (`globPatterns`): the app shell — HTML, JS, CSS, icons and
  `sounds/glasswave-notification.mp3`, so a cold offline start works and a
  reminder still plays its sound. ~2 MB, 21 entries.
- **Google Fonts**: `StaleWhileRevalidate` for the stylesheet, `CacheFirst`
  (1 year) for the font files.
- **Firebase**: deliberately not cached by the service worker. Firestore has its
  own IndexedDB offline persistence, and its requests are not plain cacheable
  GETs.

Updates use `registerType: "autoUpdate"` with `skipWaiting` + `clientsClaim`: a
new deploy is picked up on the next visit without a prompt.

## Native shell

`registerServiceWorker()` returns early when `Capacitor.isNativePlatform()` is
true (and in dev builds). Inside the Android/iOS shell the same assets are
already on the device, so a second cache layer would only add confusion.

## Testing it locally

```bash
npm run build
npm run preview       # or: npx vite preview --host
```

Then in DevTools → Application: _Manifest_ should list GlassWave, _Service
Workers_ should show `sw.js` as activated, and the app should still load with
_Offline_ ticked. The service worker only runs in a production build over
HTTPS (or `localhost`).

## Platform notes

- **Android / desktop Chrome**: real install prompt, standalone window, offline.
- **iOS Safari**: "Share → Add to Home Screen" works and now has an offline
  shell too. Background reminders still do **not** work in the PWA — iOS has no
  scheduled local notifications for web apps, and Web Push would need a service
  worker push handler plus a backend (not implemented). Reminders in the browser
  fire from the in-app 30-second poller, i.e. only while the app is open; for
  true background reminders on iOS, use the native build (`ios-capacitor/`).
