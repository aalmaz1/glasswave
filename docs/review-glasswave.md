# GlassWave — полная оценка приложения

Дата: 2026-08-19. База: `main` @ `ca4d4a2`. Оценка по всем аспектам + один консолидированный промпт изменений.

---

## 1. Краткий вердикт

**Web-версия (React + Vite + Capacitor) — сильная, зрелая.** Хорошая производительность (продуманная мемоизация, parallax без ре-рендеров), аккуратная работа с Firestore (офлайн-кэш IndexedDB, отложенная запись, обработка ошибок), солидные security rules, качественная локализация и дизайн.

**Flutter-версия — прототип, оторванный от основной архитектуры.** Это локальное приложение (только `SharedPreferences`) с фейковой авторизацией и без облачной синхронизации. Оно никак не связано с web-версией — ни по данным, ни по моделям. Заявленный «cross-platform sync» на мобильной стороне фактически отсутствует.

**Главные системные проблемы:**
1. Два независимых приложения с разными моделями данных и разной логикой (web ≠ Flutter).
2. Дублирование переводов в двух местах (`src/i18n/index.tsx` и `assets/translations/*.json`) — уже разошлись.
3. Полное отсутствие тестов и линтеров (при том что README их декларирует).
4. Жёсткий лимит 500 заметок без пагинации.
5. Доступность (a11y) ниже приемлемого уровня.

Оценка по аспектам (из 10):

| Аспект | Балл | Комментарий |

## 2. Разбор по аспектам

### 2.1 Архитектура

**Плюсы**
- Чёткое разделение слоёв в web: `firebase.ts` (конфиг) → `useFirestoreQuery` (подписка) → `App.tsx` (оркестрация) → memo-компоненты.
- Продуманные замечания-комментарии о том, *почему* сделано именно так (отложенная запись, отсутствие `orderBy` из-за композитного индекса, parallax без state).
- `ErrorBoundary` с локализованным экраном восстановления.

**Проблемы**
- `src/app/App.tsx` — 2185 строк в одном файле: темы, CSS, типы, auth, миграция, все экраны и модалки. Тяжело поддерживать.
- **Два приложения:** `src/` (React) и `lib/` (Flutter) не делят ни модели, ни логику. Модель заметки в Dart (`lib/models/note.dart`) не совпадает с TS-типом `Note` (нет `createdAt`, `firestoreId`; поле `reminder` nullable — ок, но остальное расходится).
- Flutter не использует Firebase вообще (`pubspec.yaml` без firebase-пакетов). «Синхронизация между устройствами» из README на мобильном не работает.

### 2.2 Web-фронтенд (React)

**Сильные стороны**
- Отличная работа с производительностью: `React.memo` на карточках, стабильные колбэки через `allNotesRef`, локальный draft в `EditorModal` (тайпинг не рендерит всё приложение), parallax через мутацию DOM.
- Ручное разбиение чанков (`vendor-firebase`, `vendor-tiptap`, `vendor-react`) в Vite — разумно.
- Учтён Android back-button и system bars через Capacitor.

**Замечания**
- Нет code-splitting самих экранов (настройки/редактор грузятся всегда — минорно, т.к. всё в одном бандле).
- `useTheme` содержит дублированную логику инициализации (в `useState`-инициализаторе и в `useEffect`) — риск рассинхрона.
- Мёртвый код: ключ перевода `loadMore` объявлен, но нигде не используется (пагинации нет).

### 2.3 Flutter-версия

- Хранение **только в `SharedPreferences`** (`persistence_service.dart`), «авторизация» — самописная проверка SHA-256-хеша, хранящегося на устройстве. Это не настоящая аутентификация и не синхронизация.
- Есть устаревший «legacy plaintext pw»-миграционный путь — лишняя сложность для прототипа.
- UI есть (glass-контейнеры, орбы, карточки, редактор с markdown-превью), но функционально это другая программа.
- `settings_sync_desc` в JSON-переводах обещает облако, которого нет в Flutter-коде.

### 2.4 Firebase / бэкенд / безопасность

**Сильное**
- `firestore.rules`: whitelist полей (`hasOnly`), проверка типов и размеров, неизменяемость `ownerUid` и `createdAt`, приватность по владельцу. Это заметно выше среднего.
- `initializeFirestore` с `persistentLocalCache` + multi-tab менеджер — офлайн работает грамотно.
- Миграция гостевых заметок через `writeBatch` с защитой от повторных запусков (`dirty`-флаг).

**Риски / замечания**
- **Закоммичен живой конфиг Firebase** (`src/firebase.ts`): реальные `apiKey`, `projectId=glasswave-4f5da`, `appId` как fallback-значения по умолчанию. Firebase web-ключи формально не «секрет», но жёстко пришивать чей-то боевой проект и отправлять в него трафик по умолчанию — плохая практика. Правильнее: без `.env` показывать ошибку конфигурации или явный «демо»-режим.
- Нет верификации email (`sendEmailVerification` не вызывается), нет сброса пароля (`sendPasswordResetEmail` отсутствует — пользователь, забывший пароль, не может восстановить доступ).
- Ошибки входа логируются через `console.error(err.code, err.message)` — в проде лучше не писать детали в консоль.
- `README`-пример `.env` использует `storageBucket=...firebasestorage.app`, а в коде `.firebasestorage.app` — расхождение.

### 2.5 Модель данных / синхронизация

- **`id` заметки = `Date.now()`** (миллисекунды). Два устройства/две заметки в одну миллисекунду → коллизия; `id` используется как React-key и ключ мутаций.
- **`NOTES_FETCH_LIMIT = 500`** — жёсткий потолок без пагинации; 501-я заметка молча невидима. (Отсутствие `orderBy` ради избежания композитного индекса — осознанный компромисс, но тогда нужен курсор по `updatedAt`.)
- Нет разрешения конфликтов (last-write-wins целиком по документу) — приемлемо для заметок, но стоит зафиксировать.
- Напоминания: на web — опрос каждые 30с (работает только при открытой вкладке), на native — локальные уведомления. Согласованности между ними нет.

### 2.6 i18n

- 3 языка (ru/en/ko), корректная плюрализация русского («слово/слова/слов»).
- **Два источника правды**: TS-словарь (`src/i18n/index.tsx`) для web и JSON (`assets/translations/*.json`) для Flutter. Ключи уже разошлись (`search_hint` vs `searchPlaceholder` и т.д.) — гарантированный дрейф.
- `editingNote` пуст во всех языках (заглушка).

### 2.7 Доступность (a11y)

Проблемы (важные):
- **Карточки заметок — `<div onClick>`**: не фокусируемы с клавиатуры, нет `role="button"`, `tabIndex`, `onKeyDown`. Скринридер/клавиатура не могут открыть заметку.
- **Модалки**: нет focus-trap, фокус не переносится в диалог при открытии, фон не `aria-hidden`, `Esc` обрабатывается только в редакторе.
- Контраст вторичного текста `rgba(255,255,255,0.30)` и 0.60 на тёмном — ниже WCAG AA.
- Нет поддержки `prefers-reduced-motion` (анимации карточек/модалок/колокольчика).

Хорошее: много `aria-label`, `aria-pressed` у тем, `role="alert"`, `aria-live`.

### 2.8 UX / дизайн

- Glassmorphism реализован на уровне (градиентные кольца, sheen, hover-состояния, 12 тем).
- Плавные анимации, bottom-nav, FAB, sheets — аккуратно.
- **Нет автосохранения** в редакторе: закрытие вкладки браузера теряет черновик (промпт «несохранённые изменения» срабатывает только на внутри-app закрытие).
- Нет выбора цвета заметки (accentIdx назначается случайно), нет тегов/папок, нет экспорта/импорта — потенциальные фичи, но не баги.

### 2.9 Тестирование / качество

- **0 тестов** (ни unit, ни e2e, ни widget).
- **Нет ESLint/Prettier**, хотя README в «Code Style Guide» прямо обещает «React: ESLint + Prettier».
- `typecheck` (`tsc --noEmit`) есть, но не прогоняется локально без `node_modules`; в CI прогоняется (хорошо).

### 2.10 CI/CD

- Только `.github/workflows/apk_build.yml`: сборка APK + релиз. Осмысленно (typecheck как гейт, подпись, `--generate-notes`).
- Нет: workflow для web-деплоя (Firebase Hosting), шага `lint`, шага тестов, проверки Dart (`flutter analyze`/`flutter test`).

### 2.11 Документация

- README подробный, но содержит **несуществующие фичи**: «RSS integration» — в коде RSS нет вообще.
- «Flutter 3.12+», «Firebase синхронизация на мобильном» — не соответствуют фактическому (локальному) состоянию Flutter-части.
- Нет `CONTRIBUTING.md`, нет changelog. `llms.txt` и `robots.txt` есть (хорошо).

### 2.12 SEO / PWA

- `manifest.webmanifest`, иконки, OG/Twitter-теги, `viewport-fit=cover` — есть.
- Нет `sitemap.xml`, нет structured data. Для SPA-заметочника SEO некритично, но OG-превью завязано на `./icons/icon-512.png` (ок).
- `lang="ru"` захардкожен в `index.html` и подменяется JS в рантайме — стартовый язык страницы всегда `ru` до гидрации (мелочь).

## 3. Приоритизированный список изменений

1. Заменить закоммиченный fallback-конфиг Firebase на обязательную конфигурацию + понятную ошибку при отсутствии `.env`.
2. Добавить сброс пароля (`sendPasswordResetEmail`) и верификацию email.
3. Исправить коллизии `id` (UUID/`crypto.randomUUID()` вместо `Date.now()`).
4. Убрать дублирование переводов: сделать `src/i18n/index.tsx` единственным источником (или наоборот), генерируя JSON.

**P1 — функциональность и a11y**

7. Focus-trap и управление фокусом в модалках + `prefers-reduced-motion`.
8. Автосохранение черновика (debounce) в редакторе.

**P2 — качество и процесс**

10. Добавить минимальный набор unit-тестов (утилиты: `stripHtml`, `fmtDate`, `coerceDate`, i18n) + Vitest.
11. Расширить CI: web-деплой, `lint`, `test`, `flutter analyze`.
12. Синхронизировать README с реальностью (убрать RSS, скорректировать мобильный раздел).

**P3 — стратегически (отдельным решением)**
13. Решить судьбу Flutter-версии: либо подключить Firebase (Auth + Firestore) и поднять её до паритета, либо явно пометить как «локальную» и убрать обещания синка.
14. Разбить `App.tsx` на модули.
